Modal

A modal is a focused overlay that interrupts the current flow to capture a decision or a short task. It dims the page behind a centered card, holds the user's attention on a single action, and returns them to where they were once dismissed. Use modals sparingly — only when the interruption is justified.

Overview / Anatomy

A modal is built from an overlay and a container that holds four stacked regions. Each region has a defined role.

ElementDescription
1
 Overlay Dimmed backdrop (rgba(0,0,0,0.4)) that covers the page and centers the container. Clicking it dismisses the modal. Class hb-modal-overlay.
2
 Container White card, max-width 720px, border-radius-16, shadow-floating. Holds the regions below. Class hb-modal.
3
 Header Title (hb-modal__title) plus an × close button (hb-modal__close). Class hb-modal__header.
4
 Body The content area — a short message, form fields, or details. Class hb-modal__body.
5
 Footer Right-aligned action buttons — the primary action sits last. Class hb-modal__footer.

Types

Modals share one structure but differ in their footer action pattern, which signals the nature of the decision.

TypeWhen to useFooter
Informational Communicate something the user only needs to acknowledge.
Confirmation Ask the user to confirm a reversible action before it proceeds.
Danger Confirm a destructive, irreversible action such as delete or revoke.
Form Collect a small amount of input without leaving the current view.

Best practices

Do

Use specific button labels that name the action being confirmed.

Always provide a way to dismiss — close button, Cancel, overlay click, and Esc.

Keep content concise. A modal is for a single, focused decision.

Don't

Don't use vague labels like "OK" or "Yes" — they hide what will happen.

Don't stack modals on top of one another. Resolve one before opening the next.

Don't use a modal for success or error toasts — use a transient notification instead.
