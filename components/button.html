Button

Buttons enable users to perform actions. They create a clear visual hierarchy, offer predictable affordance, and support efficient workflows. A consistent button system ensures clarity, reduces cognitive load, and maintains a cohesive experience across interfaces.

Types

Each button type represents a different level of emphasis and should be used intentionally to establish a clear visual hierarchy.

Primary Highest emphasis. The main action in a view. Use sparingly — one per page. 
<button class="hb-btn hb-btn--primary hb-btn--lg">Submit</button>
Secondary Medium emphasis. Most standard actions. The default go-to button. 
<button class="hb-btn hb-btn--secondary hb-btn--lg">Export</button>
Tertiary Lightweight text button. Visible but minimal — no background surface. 
<button class="hb-btn hb-btn--tertiary hb-btn--lg">Learn more</button>
Ghost Lowest emphasis. For non-critical or contextual actions. No border, no background. 
<button class="hb-btn hb-btn--ghost hb-btn--lg">Cancel</button>
Confirmation Positive high-clarity. Confirms successful or approved outcomes. Reinforces confidence. 
<button class="hb-btn hb-btn--confirmation hb-btn--lg">Approve</button>
Danger Destructive actions. Signals irreversible or harmful operations. Use only for delete/revoke. 
<button class="hb-btn hb-btn--danger hb-btn--lg">Delete record</button>

Sizes

Two sizes are available. Large is the default across the platform. Small is reserved for dense or compact environments.

Size Class Height Padding Use for
hb-btn--lg 40px 8px / 12px Default. Most views, forms, dialogs
hb-btn--sm 32px 8px Dense tables, compact toolbars, banners

Full width

Use hb-btn--full-width when a button should fill its container — common in mobile layouts, confirmation modals, or dedicated action areas.

<button class="hb-btn hb-btn--primary hb-btn--lg hb-btn--full-width">Submit form</button>

Usage

Choose the button type based on the action's importance and context within the interface.

TypeUse forAvoid
Main action: Submit, Save, Create, Send More than one per view. Secondary navigation.
Standard actions alongside a primary: Export, Filter, Edit Replacing primary in high-stakes flows
Supporting actions: Learn more, View all, See details Primary actions or anything destructive
Cancel, Back, Dismiss — low friction exits Main actions. Can be confused with disabled.
Approve, Resolve, Mark as complete Everyday actions — reserve for positive outcomes
Delete, Revoke, Remove — irreversible actions only Reversible actions. Always pair with a confirmation modal.

Best practices

Do

Pair a primary action with a ghost or secondary to create clear hierarchy.

Use specific, action-oriented labels. "Save changes" over "OK".

Use Danger only for irreversible, destructive actions. Always confirm first.

Don't

Don't use multiple primary buttons in the same view.

Avoid vague labels like "OK", "Yes", "Confirm". Be specific.

Don't use Danger for non-destructive actions.
