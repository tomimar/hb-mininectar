Components

Sidenav

The secondary navigation inside a page — the list of sections of a Profile, a Case or Settings. Items can carry an icon, a count and a submenu, and groups expand and collapse. The nav itself can also be collapsed away entirely, handing its width to wide content such as a table and floating back when it is hovered.

Overview

One item per page section. The current section is marked by a grey fill and a heavier weight — never by colour alone. A submenu breaks a section into its sub-sections.

Items and icons

An item is a plain label at minimum. Add a leading icon when the nav lists destinations of different kinds — Settings does, a Profile's sections do not. Whichever you choose, apply it to every item in the nav: one icon among plain labels reads as an error.

With counts

A hb-sidenav__count after the label tells how many records a section holds, so the user knows what is worth opening before opening it. Use it only where the number changes something — and leave the count off rather than showing a 0: an empty section is better told by the empty state inside it.

Submenus

A section with sub-sections gets an expandable item: a <button> carrying aria-expanded and a chevron, plus a hb-sidenav__submenu list. The submenu hangs off a rail line, and the active sub-item darkens its own segment of that rail. Keep nesting to one level.

Collapsing

Wide content — a table with ten columns — competes with the nav for horizontal space. Collapsing hands that space back. Nothing is left behind: no rail, no strip of icons. The nav leaves the layout entirely and only its toggle stays, in the page header.

It is not gone, though. Hovering the toggle floats the nav back over the content, live and clickable, so jumping to another section never costs a click on the way. Move away and it retreats; click the toggle and it is pinned open again. Same pattern as Notion's sidebar.

Collapse the nav, then hover the toggle that stays behind — the nav floats back without being pinned.

Two classes carry the whole behaviour, on top of a hb-sidenav-area wrapper: is-collapsed takes the nav out of the layout and hides it, and is-peeking floats it back. A short delay on leaving keeps the panel from flickering while the pointer travels from the toggle to the nav.

<div class="hb-sidenav-area"
     x-data="{ collapsed: false, peek: false, timer: null,
               show() { clearTimeout(this.timer); this.peek = true },
               hide() { clearTimeout(this.timer); this.timer = setTimeout(() => this.peek = false, 200) },
               pin()  { clearTimeout(this.timer); this.collapsed = !this.collapsed; this.peek = false } }">

  <nav class="hb-sidenav" id="settings-nav" aria-label="Settings"
       :class="{ 'is-collapsed': collapsed, 'is-peeking': collapsed && peek }"
       @mouseenter="collapsed && show()" @mouseleave="collapsed && hide()">
    <div class="hb-sidenav__header">
      <span class="hb-sidenav__title">Settings</span>
      <button type="button" class="hb-sidenav__toggle" @click="pin()"
              aria-expanded="true" aria-controls="settings-nav"
              aria-label="Collapse navigation">
        <span class="hb-icon" aria-hidden="true">first_page</span>
      </button>
    </div>
    …
  </nav>

  <main>
    <!-- the way back: only shown once the nav is collapsed -->
    <button type="button" class="hb-sidenav__toggle" x-show="collapsed" x-cloak
            aria-expanded="false" aria-controls="settings-nav"
            aria-label="Expand navigation"
            @mouseenter="show()" @mouseleave="hide()"
            @focus="show()" @blur="hide()" @click="pin()">
      <span class="hb-icon" aria-hidden="true">last_page</span>
    </button>
    …
  </main>
</div>
info
Remember the choice. A user who collapses the nav to read a wide table expects it to stay collapsed on the next page — persist the state (localStorage) per user, not per page.

Behaviour

accessibility_new
What the markup has to carry.
  • The container is a <nav> with an aria-label — a page often has two navs (the app rail and this one), and they must be told apart.
  • Destinations are <a>; things that expand are <button> with aria-expanded and aria-controls pointing at the submenu.
  • The current item is marked with aria-current="page", not only with the --active class — fill and weight are for the eye, aria-current is for the screen reader.
  • A collapsed nav is hidden with visibility, so its links leave the tab order — no focus ever lands on something invisible.
  • Hover-to-peek is a shortcut for pointer users, never the only way in: the toggle is a real button that expands the nav on click or Enter. It also peeks on focus, so a keyboard user sees what they are about to open.
  • The toggle's own name changes with its state — “Collapse navigation” / “Expand navigation” — and it carries aria-expanded.
  • Icons are decorative (aria-hidden); the label carries the meaning.
  • Transitions are dropped under prefers-reduced-motion.

Guidelines

check Do
Offer the collapse toggle wherever the nav sits next to a table or another wide surface.
Keep the toggle visible in the page header once the nav is collapsed.
Let the peeking nav be fully usable — a user should be able to navigate from it without pinning it first.
Show a count only where the number is worth acting on.
Keep the current sub-item's parent marked as active as well.
Persist the collapsed state across pages.
close Don't
Leave a strip of icons behind — collapsed means collapsed, the content gets the full width.
Make hover the only way to bring the nav back.
Nest more than one level of submenu; flatten the section instead.
Use this for the app's primary navigation — that is the global rail, a different component.
Signal the current item by colour alone, or show a count of 0.
